# PatchPilot demo script (about 2 minutes)

Target: **1–3 minutes** for the OpenFire Hackathon X post.

Live app: <https://patchpilot-gamma.vercel.app>

> **Disclosure to say out loud:** the current deployment runs in **Sample mode** (deterministic local rules), because no model-provider key is configured in production. The UI labels this in the header and the banner. The same build runs live open-model inference when `OPENROUTER_API_KEY` is set; that path was verified during development against an OpenAI-compatible endpoint. Do not describe the deployed demo as live AI unless `/api/status` says `provider.mode: live`.

## Preparation

1. Open <https://patchpilot-gamma.vercel.app> in a calm browser window, zoomed to about 110%.
2. Close other tabs so the URL bar is visible.
3. Have this script next to the recording window.

## Script

**0:00–0:15 — Problem**

> "AI code review is easy to generate and hard to trust. Models invent line numbers and quote code that was never submitted. PatchPilot only shows a finding if its evidence actually exists in the code."

Show the header and the one-line product description.

**0:15–0:35 — Submit the sample diff**

Click **Diff sample**. Point at the status strip and the **Bundled sample** chip.

> "This is a real checkout module with a genuine discount bug, two SQL injection sinks, and a fallback JWT secret. I'll click Analyze changes."

Click **Analyze changes**. Note the loading state; the findings appear in a second or two.

**0:35–1:05 — Evidence-backed findings**

Point at the severity counts: 2 critical, 2 high, 2 medium, 1 low, 1 informational.

Open **SQL injection in the coupon lookup**. Show:

- `src/checkout.ts:9-11` — the real location, recomputed from the diff.
- **Evidence verified** badge and the quoted lines.
- **Why it matters** and **Suggested fix**.

> "The line numbers are not from the model. PatchPilot re-parses the diff and recomputes the location, then drops any finding whose quote it cannot find."

Open **Discount treats a percentage as a fraction** briefly.

> "A 20% coupon becomes a negative total — a bug people actually ship."

**1:05–1:25 — Ask**

Switch to the **Ask** tab. Ask: *"What should I fix first?"* Then *"Which security issue is most serious?"*

> "Answers are grounded in the verified findings. In sample mode they're generated deterministically, and it says so at the top of every answer."

**1:25–1:40 — Tests**

Open the **Tests** tab and click **Generate tests**.

> "Up to three structured suggestions — test type, setup, expected result, and which finding it covers. It does not pretend to write or run your test suite."

**1:40–1:55 — Report**

Open the **Report** tab, scroll the Markdown preview, click **Download**.

> "A deterministic Markdown report: metadata, counts, evidence, fixes, warnings, and limitations. Nothing is regenerated by a model, so it matches exactly what you reviewed."

**1:55–2:10 — Honesty and architecture**

Point at the status pill in the header.

> "The header distinguishes 'Live configured' from 'Live verified'. This deployment is sample mode, clearly labelled. The same code runs real open-model inference when a provider key is set — the key stays server-side, prompts and output are never logged, and submitted code is never executed. There's also an MCP endpoint so Alan agents can call PatchPilot's review tools directly."

End on the deployment URL.

## Alternate take: safe code

If you want to show the false-positive discipline, paste:

```ts
export function add(a: number, b: number): number {
  return a + b;
}
```

Click **Analyze changes**. Only an informational "no tests accompany this code" note appears — no invented vulnerabilities.

## Do not claim

- Do not say the deployment is running live AI; it is sample mode.
- Do not claim findings are verified vulnerabilities. Evidence is verified; exploitability is not.
- Do not show any API key or environment variable value on screen.
